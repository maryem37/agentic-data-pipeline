Why this project

Less time translating intent into operations.

A learning project in agent orchestration that brings common data tasks behind one natural language entry point.

01 / ONE ENTRY POINT

Start with the goal, not the syntax.

Describe the analysis or file operation you want. The agent selects a specialist path and connects your request to its tools.

02 / MODULAR

Separate responsibilities.

SQL work and ETL work live in distinct agents, making the workflow easier to understand and extend.

03 / PRACTICAL

Move between data tasks.

Query a PostgreSQL database or work with API and file data using familiar Python and pandas operations.

04 / BUILT TO LEARN

Explore LangChain tools and LangGraph routing in a hands-on data engineering project.

When to use it

Choose the path that matches your task.

Use Data Agent for focused database analysis and straightforward extract-transform-load work.

Use SQL path

When the data is already in PostgreSQL

Ask for filters, counts, groupings, or comparisons across available database tables.

“How many rides were completed by each vehicle type?”
Use ETL path

When you need to bring in or reshape data

Extract from an API, transform a supported local file, and save the result as CSV, JSON, or Parquet.

“Load this CSV, keep completed payments, and save the result as Parquet.”
Good fit

Repeatable, well-scoped tasks

Give a clear source, a specific operation, and an output location or format to help the agent act precisely.

“Fetch the Pokémon API results and save them to data/extract as CSV.”
Plan first

Tasks needing production controls

Review generated queries and transformations before using them on sensitive or business-critical data. This project is a prototype and does not provide a production approval workflow.
